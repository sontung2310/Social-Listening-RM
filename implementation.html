Extend data sources

The listening tool collects posts from Reddit, news APIs, and similar sources via a shared fetch(query, limit) → list[dict] contract. This part covers new sources beyond the original registry.

X (Twitter) via Playwright

Overview

Module Backend/Backend/api/sources/x_playwright.py crawls X with Playwright (not the paid X API). It reuses a logged-in browser session via cookies (X_AUTH_TOKEN, X_CT0 as module globals), then either searches by keywords or opens a user profile. Results match the same post shape used by Reddit/news sources.

Entry points: fetch() (search), fetch_profile() (profile). Source keys: x_playwright, x_playwright_profile. Not registered in __init__.py yet — run via CLI or direct import.

Architecture

ClassRole
XPlaywrightClient Browser session, cookies, scroll, tweet DOM parsing
XSearchCrawler Search URL + Advanced Search operators
XProfileCrawler Profile timeline (https://x.com/{user})

Class composition

flowchart LR
  search[XSearchCrawler] --> client[XPlaywrightClient]
  profile[XProfileCrawler] --> client
  client --> browser[Chromium]
  browser --> xsite[x.com]
  client --> rows[Post dicts]

How it works

Navigation is URL-driven (no search-bar typing or tab clicks). Search opens /search?q=…&f=live|top; profile opens /username. The client waits for article[data-testid="tweet"], parses posts, then scrolls with random delays (human_delay) up to X_MAX_SCROLLS.

Crawl flow (search and profile share the client)

flowchart TD
  start[Start fetch] --> auth{Cookies set?}
  auth -->|No| empty[Return empty list]
  auth -->|Yes| url[Build search or profile URL]
  url --> open[Open page with Playwright]
  open --> wait[Wait for tweet articles]
  wait --> wall{Login wall?}
  wall -->|Yes| empty
  wall -->|No| loop[Parse tweets then scroll]
  loop --> done[Return normalized rows]

Search supports X Advanced Search operators when set (empty = skip): since: / until:, min_replies: / min_faves: / min_retweets:. Tab filter: live (Latest / time order) or top (popularity). Explicit args override module globals.

Output shape

{
  "post_id": "x_playwright:{status_id}",
  "source": "x_playwright",
  "url": "https://x.com/{user}/status/{id}",
  "title": "truncated text",
  "text": "plain tweet body",
  "published_ts": 1710000000,
  "author": "@user",
  "domain": "x.com",
  "engagement": { "likes", "retweets", "comments", "views" }
}

CLI

# Search
python -m api.sources.x_playwright search --query "AI" --limit 5 --filter live \
  --since 2026-07-14 --until 2026-07-16 --min-faves 50

# Profile
python -m api.sources.x_playwright profile --user Roboticmarketer --limit 10

Search flags: --query, --limit, --filter, --since, --until, --min-replies, --min-faves, --min-retweets, --json. Profile flags: --user (required), --limit, --json. Run from code/Backend/Backend.

Tech stack

  • Python + Playwright Chromium (playwright>=1.49.0; playwright install chromium)
  • requests for advisory robots.txt check
  • Helpers in utils.py: clean_html_to_text, human_delay, parse_engagement_count, truncate_title

Use cases

  • Topic discovery — keyword search with optional date / engagement filters
  • Account monitoring — crawl a profile timeline (handle or URL)
  • Standalone testing — CLI without wiring into REGISTRY / views.py

Limits

  • DOM selectors can break when X changes UI; cookies expire and must be refreshed.
  • Prefer a dedicated account; keep scroll delays; scraping may conflict with X ToS.
  • Set X_HEADLESS = False if headless is blocked. Views may be missing.

YouTube Data API

Overview

Module Backend/Backend/api/sources/youtube_api.py crawls YouTube via the official Data API v3 (HTTP requests, no browser). Auth is an API key loaded from credentials/backend.env as YOUTUBE_API_KEY (via config.py). Two modes: keyword search and regional trending (chart=mostPopular). Results follow the shared post contract, with extra niche-insight fields (engagement rates, trending / breakout scores, channel size, topics).

Entry points: fetch() (search), fetch_trending() (trending). Source keys: youtube_search, youtube_trending. Not registered in __init__.py yet — run via CLI or direct import.

Architecture

ClassRole
YouTubeApiClient HTTP client, region aliases, search / videos / channels batching
YouTubeSearchCrawler Keyword search → enrich video + channel stats
YouTubeTrendingCrawler Regional mostPopular chart (no keyword)

Class composition

flowchart LR
  search[YouTubeSearchCrawler] --> client[YouTubeApiClient]
  trending[YouTubeTrendingCrawler] --> client
  client --> searchEP[search.list]
  client --> videosEP[videos.list]
  client --> channelsEP[channels.list]
  client --> rows[Post dicts]

How it works

Search is a two-step enrich pipeline: search.list returns video IDs (with q, order, optional regionCode / publishedAfter), then videos.list loads snippet, statistics, and topic details, and channels.list adds subscriber counts. Rows are sorted by engagement.trending_score.

Trending calls videos.list?chart=mostPopular for a region (optional videoCategoryId). It has no keyword filter at the API level — use search for niche queries; use trending for a regional market pulse.

Crawl flow (search path)

flowchart TD
  start[Start fetch] --> key{API key set?}
  key -->|No| empty[Return empty list]
  key -->|Yes| search[search.list for video IDs]
  search --> videos[videos.list enrich]
  videos --> channels[channels.list subscribers]
  channels --> map[Map rows + compute metrics]
  map --> done[Return sorted rows]

Optional module globals (None = unset): YOUTUBE_REGION_CODE, YOUTUBE_SEARCH_ORDER, YOUTUBE_PUBLISHED_AFTER_DAYS. Runtime defaults when arg and global are both unset: order=viewCount, published_after_days=60 (pass 0 to omit the recency filter). location aliases region_code (e.g. AU / Australia → AU).

Output shape

{
  "post_id": "youtube_search:{video_id}",
  "source": "youtube_search",
  "url": "https://www.youtube.com/watch?v={id}",
  "title": "video title",
  "description": "video description",
  "text": "same as description (persist shim)",
  "published_ts": 1710000000,
  "author": "Channel Name",
  "channel_id": "UC…",
  "channel_subscriber_count": 12000,
  "video_category_id": "28",
  "video_category_label": "Science & Technology",
  "tags": ["…"],
  "topic_categories": ["https://en.wikipedia.org/wiki/…"],
  "engagement": {
    "likes", "views", "comments",
    "like_rate", "comment_rate", "views_per_day",
    "trending_score", "breakout_score"
  }
}

trending_score = views / age_days^0.6 favors recent high-view videos. breakout_score = views_per_day / subscribers flags small channels punching above their weight.

CLI

# Search
python -m api.sources.youtube_api search --query "niche marketing" --limit 10 \
  --region-code AU --published-after-days 60 --order viewCount

# Trending
python -m api.sources.youtube_api trending --limit 20 --region-code US \
  --video-category-id 28 --json

Search flags: --query, --limit, --region-code, --location, --published-after-days, --order, --json. Trending flags: --limit, --region-code, --location, --video-category-id, --json. Run from code/Backend/Backend.

Tech stack

  • Python + requests against https://www.googleapis.com/youtube/v3
  • API key via config.YOUTUBE_API_KEY / credentials/backend.env
  • No extra pip packages beyond existing Backend deps

Use cases

  • Niche discovery — keyword search with view-count order and a 30–90 day window
  • Regional pulse — trending / mostPopular for AU or US (optional category)
  • Breakout signals — small channels with high breakout_score
  • Standalone testing — CLI without wiring into REGISTRY / views.py

Limits

  • Daily quota (~10,000 units): search.list ≈ 100/call; videos.list / channels.list ≈ 1/call.
  • Trending cannot filter by keyword at the API level; use search for topic-specific crawls.
  • Missing or invalid API key returns an empty list (CLI exit code 2).

Reddit via Playwright

Overview

Module Backend/Backend/api/sources/reddit_playwright.py crawls the current www.reddit.com interface with Playwright. It reuses a logged-in browser session through the reddit_session cookie and supports two mutually exclusive modes: global keyword search and a subreddit listing such as r/digital_marketing.

Entry points: fetch() (keyword search) and fetch_subreddit() (subreddit listing). Source keys are reddit_playwright, reddit_playwright_subreddit, and reddit_playwright_comments. Each call returns {"posts": [...], "comments": [...]}. The module is standalone: it is not registered in api/sources/__init__.py and does not persist results.

Architecture

ClassRole
RedditPlaywrightClient Chromium session, cookies, navigation, scrolling, and post DOM parsing
RedditSearchCrawler Builds /search/ URLs and runs global keyword searches
RedditSubredditCrawler Normalizes subreddit names and builds /r/{name}/{sort}/ URLs
RedditCommentsCrawler One visit per post: enrich metadata; optionally collect comments on the same page

Class composition and crawl flow

flowchart LR
  search[RedditSearchCrawler] --> client[RedditPlaywrightClient]
  subreddit[RedditSubredditCrawler] --> client
  client --> browser[Chromium]
  browser --> reddit[www.reddit.com]
  client --> posts[Post rows]
  posts --> visit[Open each post once]
  visit --> enrich[Enrich metadata]
  enrich --> comments{Include comments?}
  comments -->|Yes| commentCrawler[Collect comments same visit]
  comments -->|No| result[CrawlResult]
  commentCrawler --> result

How it works

Navigation is URL-driven. Keyword mode opens /search/?q={query}&type=link; type=link selects Reddit's Posts results. Subreddit mode opens /r/{subreddit}/ or /r/{subreddit}/{sort}/. Inputs such as r/digital_marketing, /r/digital_marketing/, and a Reddit subreddit URL are normalized to the subreddit name.

Reddit renders the two modes differently. Subreddit feeds and post pages use <shreddit-post>, while search uses [data-testid="sdui-post-unit"]. The client waits for either selector, extracts visible cards, deduplicates by Reddit post ID, and scrolls with random delays until it reaches the requested limit or no new cards appear.

ModeAllowed sort valuesTime filter behavior
Keyword search relevance, hot, top, new, comments t= is applied with top or relevance
Subreddit hot, top, new, best, rising t= is applied only with top

Valid time values are hour, day, week, month, and year. If a time filter is supplied with an unsupported sort (for example, subreddit hot plus week), the crawler logs a warning and omits t= from the URL. Invalid sort or time values raise ValueError.

Post and comment extraction

Feed/search listing cards are collected first (title, permalink, and whatever engagement Reddit shows on the card). The crawler then opens each post page once to enrich metadata from <shreddit-post>: author, self-text/caption, publication time, domain, subreddit, and engagement fields when present. It does not download images or video and does not fetch outbound link contents.

If include_comments=True, comments are collected during that same post-page visit (no second navigation). Nodes are <shreddit-comment>, returned as a flat list. num_comment_crawl limits top-level comments to a hard cap of 50; get_replies=True also includes nested replies and sets parent_comment_id.

Output shape

{
  "posts": [{
    "post_id": "reddit_playwright:{reddit_id}",
    "source": "reddit_playwright",
    "url": "https://www.reddit.com/r/{sub}/comments/{id}/...",
    "title": "post title",
    "text": "self-text or caption",
    "text_html": "raw body HTML when available",
    "published_ts": 1710000000,
    "author": "reddit_username",
    "domain": "self.subreddit or linked domain",
    "subreddit": "digital_marketing",
    "engagement": {
      "upvotes": 42,
      "comments": 7,
      "share": null
    }
  }],
  "comments": [{
    "comment_id": "reddit_comment_id",
    "source": "reddit_playwright_comments",
    "parent_content_id": "reddit_post_id",
    "parent_content_url": "https://www.reddit.com/r/...",
    "author": "reddit_username",
    "text": "comment text",
    "like_count": 5,
    "reply_count": 2,
    "parent_comment_id": null,
    "published_ts": 1710000000
  }]
}

The subreddit mode uses reddit_playwright_subreddit in the post source and post_id prefix. The share value is the crosspost/repost count only when Reddit exposes one in the DOM; otherwise it is null. It is not a general share-click count.

CLI

# Keyword search: top posts from the past week, including comments
python -m api.sources.reddit_playwright search --query "AI marketing" --limit 5 \
  --sort top --time-filter week --include-comments --num-comment-crawl 3 --json

# Subreddit listing: hot posts plus nested replies
python -m api.sources.reddit_playwright subreddit \
  --subreddit r/digital_marketing --limit 5 --sort hot \
  --include-comments --num-comment-crawl 3 --get-replies --json

Shared flags: --limit, --sort, --time-filter, --include-comments, --num-comment-crawl, --get-replies, and --json. Search adds --query; subreddit mode requires --subreddit. Run from code/Backend/Backend.

Tech stack

  • Python + Playwright Chromium against https://www.reddit.com
  • Logged-in session via module globals REDDIT_SESSION and optional REDDIT_TOKEN_V2
  • requests for an advisory robots.txt check
  • Shared helpers in utils.py for delays, text cleanup, title truncation, and engagement parsing

Use cases

  • Topic discovery — search Reddit posts globally by keyword
  • Community monitoring — collect posts from one named subreddit
  • Conversation analysis — collect top-level comments and optional reply relationships
  • Standalone testing — CLI or direct import without changing REGISTRY

Limits

  • Reddit can change shreddit-post, search-card, or comment markup, which can break selectors.
  • Session cookies expire and must be refreshed.
  • Every crawl opens each collected post once to enrich metadata (and comments when requested), so it is slower than listing-only scrapes.
  • Search listing cards alone are sparse; enriched fields come from the post page. share stays null when Reddit does not expose a crosspost count.
  • Use conservative delays and ensure crawling complies with Reddit's terms and applicable policies.

Data pipeline design plan

Historical note (Aug 2026): Kafka was removed from Pace-Unit. Current architecture uses SQS + sibling repo Data-Crawler-Task — see SYSTEM_ARCHITECTURE.md and FUTURE_WORK.md. The Kafka diagrams below are retained as design history only.

Decouple crawling, persistence, and AI processing with Kafka. Keep one MongoDB database, while separating posts and comments because their raw and AI schemas differ.

Workflow key: blue nodes are Kafka topics; green cylinder nodes are MongoDB collections.

  1. Create a history record for the crawl/search run.
  2. Each source fetches and normalizes data, then publishes posts and comments separately.
  3. Raw consumers upsert MongoDB documents and publish successful records to the shared AI input topic.
  4. AI workers process both entity types and publish results with content_type.
  5. The result consumer routes each event to the matching AI collection; the API reads processed data.

Design decisions

Kafka: five topics

TopicPurpose
ingest.raw.postsArticles, social posts, and videos
ingest.raw.commentsComments and replies from every platform
pipeline.ai.inputPersisted posts and comments ready for AI
pipeline.ai.resultsAll completed AI results, routed by content_type
ingest.dlqEvents that still fail after bounded retries

Topics represent pipeline stage and entity shape, not source. A source field identifies Reddit, YouTube, BBC, and others. Keep one AI input and one AI result topic until post and comment workloads require different models, scaling, retention, or service-level objectives.

MongoDB: one database, six collections

CollectionResponsibility
raw_postsOriginal articles, posts, and videos
raw_commentsOriginal comments and reply relationships
ai_postsPost-level ranking, summaries, sentiment, tags, and metadata
ai_commentsComment-level sentiment, topics, intent, and other analysis
historyCrawl/search parameters, progress, and completion status
company_profilesCompany data and aggregated AI cards

Use the existing pace_database; do not create a database or collection per source. Keep comments separate instead of embedding them in posts because the relationship is one-to-many and comments need independent indexing, analysis, and retention.

Implementation contract

Event envelope

{
  "event_id": "stable-id-for-deduplication",
  "schema_version": 1,
  "event_type": "raw_collected | raw_persisted | ai_completed",
  "content_type": "post | comment",
  "source": "reddit_playwright",
  "external_id": "platform-content-id",
  "parent_content_id": null,
  "history_id": "crawl-or-search-run-id",
  "occurred_at": "ISO-8601 UTC",
  "payload": {}
}
  • Use external_id from the platform; fall back to a canonical URL hash.
  • For comments, parent_content_id identifies the post/video; keep parent_comment_id in the payload for replies.
  • Use unique keys (source, external_id) for raw data and (history_id, source, external_id) for AI data.
  • Partition raw topics by source:external_id and AI topics by content_type:external_id to preserve per-entity ordering.
  • Use at-least-once delivery. Upsert with unique keys and commit Kafka offsets only after the MongoDB write or output publish succeeds.
  • Retry transient failures with backoff; send invalid or exhausted events to ingest.dlq with the error and original event.

Code ownership and migration

  • api/sources/*: fetch, normalize, and publish only; no direct MongoDB writes.
  • persist.py: evolve into idempotent raw and AI MongoDB writer services.
  • ranking_algorithm/*: consume pipeline.ai.input and publish pipeline.ai.results.
  • views.py: create/track history and query processed collections.
  • Migrate raw_insights to raw_posts, and split ai_results into ai_posts and ai_comments.

Operational rules

  • Kafka is a transport and replay buffer; MongoDB remains the system of record.
  • Do not acknowledge an event before its durable output succeeds.
  • Carry event_id, history_id, and correlation metadata through every stage.
  • Add schema changes through schema_version; consumers must reject unsupported versions to the DLQ.
